From idea on
Skip dirty Git plugins at apply with disclosed repair guidance
In the New task form and the attach-to-card picker, when the picked externals include a GitHub/GitLab item whose repository (ExternalSummary.container) is not in projectRepos(currentProject, connection) (server/connectors/repos.ts), show a non-blocking warning naming the item and the project — e.g. "HybridRbt/paseo-sync#4 does not belong to this project's repositories. Create it here anyway?" — before the card is created/attached. Stay silent when projectRepos returns an empty list (cannot verify; do not nag) and for Jira/Confluence/Azure/Shortcut items (no repository notion). Optional, if cheap: hint which other project's repositories contain the item. Acceptance: creating a card for a foreign GitHub PR on a board shows the warning; items from the project's own repositories show none; non-git items are unaffected; the check also fires when a link or owner/repo#nr query bypasses the "This project's repositories" search scope; every new string is in all catalogs.
Why: A card created from a GitHub item on the wrong board locks its workspace to the wrong repo root: on 2026-11-05 a paseo-sync PR card was created in the flowly project (wrong project picked when creating the card from GitHub), and the session had to hunt the real checkout outside the card workspace to do the work. The repo mapping already exists and is cached (projectRepos, already scoping connector search); only the creation-time cross-check is missing. The "Everything I'm involved in" search scope and direct links/owner-repo#nr queries are exactly the paths that bypass the project scope today.
Context:
Repo: this flowly repository. Key code: client/forms.tsx (New task form; externals state ~L475, create payload with externals ~L563-566); client/connectors.tsx (ExternalPicker ~L187-300; "Search in" scope Choices ~L258-267 with values project/all; attach-to-card via rpc.createArtifact ~L341-348); server/connectors/repos.ts (projectRepos(root, baseUrl) — git remotes of the project root and first-level child repos, 5-min cache); server/connectors/service.ts:132+333 (existing projectRepos wiring, search scoping); shared/connectors.ts:99 (ExternalSummary.container carries the item's owner/repo); spec docs/CONNECTORS-SPEC.md §4.3 (project repository scope). Follow the repo rules: spec update first, t() + every catalog for new UI strings, say in the delivery note whether onboarding/tips are unaffected.
